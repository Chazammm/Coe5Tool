# Create a linked pair and prepare a test · historical version 0.7

For the current 0.8 integrated workflow, supported 5.43 / 2.13.0 pair and user-operated acceptance, see [Isolated desktop testing](ISOLATED-TEST-08.md). The statements below describe the earlier export-only phase; later local validation established the specific test-field fixture.

Checked 5 November 2026. Local Windows development only; no CoE5 process was launched, attached to or controlled. No game installation, mod, save or Script Extender source was changed. No repository push, PR, release or message was performed.

## Create and review

Choose **New spell + weapon** in the file toolbar. Enter both unique names, a built-in numeric path, level, spell damage, weapon base damage, damage type, range and initiative. Area code starts at the documented single-target value 0; choose another supported simple burst code if needed. Other required values have no automatic guesses. Optional effect/sound values start blank and are omitted when blank.

The creation subset is deliberately small: printable ASCII names (47 bytes for spells, 63 for weapon references), paths 1–69, levels 1–3, piercing/fire damage types, ordinary nonnegative damage up to 2,147,483,647, positive 32-bit range/initiative and simple area codes 0–200. These numeric restrictions define this generator, not the game's full legal ranges. Special damage masks, flags, chained weapons, custom paths and negative/special targeting codes require the usual text editor. Existing-source inspection retains its previous wider storage checks.

Documented flight modes 1–9 and flight look/sprite must be supplied together. Other optional numeric values receive syntax/storage checks only. Launch sound accepts the documented -1 mute value. The tool does not invent effect IDs, validate their presence in your installed game, play sounds or render effects. Mode 1 uses a sprite number; other modes use a look number. Refer to the game's tables and the separately labeled historical library.

Choose **.c5m** for native weapon lines followed by `#!@` spell lines, or **.c5se** for plain sidecar definitions. **Create draft & review** produces a separate generated draft and opens its prepared source. The weapon always precedes the spell and is referenced by its exact quoted name. No custom numeric ID is guessed. Names and entered numeric tokens are retained. New output uses CRLF; editing an existing file still preserves that file's own formatting, prefixes and line endings.

The draft is clearly labeled **Generated fragment**. It lacks the metadata/banner needed for a selectable mod and must be integrated into one, or used by the separate test-preparation route. **Export copy** writes a new .c5m/.c5se file. A bare .c5se also needs its matching .c5m in an actual mod. Existing source replacement requires the established unsaved-draft confirmation; it does not write to that original file. Typed creation options and generated drafts participate in native close warnings. Cancel/Escape can retain a typed form when discard is declined.

`examples/new-pair.c5m` is an example of generated syntax, not a game-tested or installable mod.

## Prepare an isolated test ZIP

For a generated pair, apply field edits and choose **Prepare test…**. Enter a unique test mod ID, existing caster and target monster names, and 1–200 targets. Names resolve in the loaded game; the workbench supplies no historical monster IDs. Use ordinary land units for this grass-field test. IDs use 1–32 letters/digits/underscores, starting with a letter; CoE5SE and Windows device names are reserved.

**Prepare files for review** shows every generated text file. Change the file selector to inspect the Lua helper, README and manifest before **Export test ZIP…**. Changing test options invalidates the previous preview. Native ZIP export always creates a new file and rejects existing paths. It never installs the ZIP or launches the game. Browser fallback permits text preparation/review but ZIP export requires the Windows host.

| Generated file | Purpose |
|---|---|
| `<ID>/<ID>.c5m` | Required mod metadata, explicit extender guard/dependency order, and definitions for combined .c5m output. |
| `<ID>/<ID>.c5se` | Present only for sidecar output; contains the generated weapon followed by its spell. The same-name .c5m supplies metadata. |
| `<ID>/<ID>.lua` | Registers a main-menu test button; does nothing until the user clicks it. |
| `<ID>/banner.tga` | Original flat 256×64, uncompressed 24-bit label generated by the native packager; contains no game artwork. |
| `<ID>/README.txt` | Dependencies, manual installation, trigger, scope, blockers and removal. |
| `<ID>/manifest.json` | Workbench version, supplied settings, source pin and `gameTested: false`. |

This is an **experimental test-mod candidate with complete source/asset structure**, not a verified runnable release. The game, extender and private reference library are not bundled. Exporting it leaves the source-fragment draft's export state separate. Only a still-canonical generated pair using its associated weapon can produce a test package; relinking it to a library weapon or entering values outside the creation subset disables preparation with a reason. Arbitrary existing source is not silently repackaged.

## Manual test, dependencies and removal

Use a disposable CoE5 profile with a legitimately installed, supported CoE5 build and CoE5SE 2.12.0. Follow the [official extender installation instructions](https://github.com/musical-pianist/coe5se/tree/669062bf21ec74cc2530ae0090f28b1ef7797c14#install). This tool does not set up a profile or install dependencies. Local Abyss launchers demonstrate isolation with COE5_SAVE/COE5_DATA and an explicit mod allowlist; they are research examples, not copied into this package. For the same process-local profile route, manually create a fresh profile folder and set COE5_SAVE to its absolute path in the launch session before starting your compatible game/extender setup. The Mods-directory command then opens that profile's directory. No global environment setting or existing profile is changed by this application.

Open the mods directory from that profile's game main menu. Extract the ZIP there, retaining its `<ID>/<ID>.c5m` structure. Enable only CoE5SE and the new test mod; return to the main menu, restarting manually if the button is absent. Do not load a campaign or start a game. `requires CoE5SE` orders enabled scripts and does not enable an absent dependency; `needs_script_extender` prevents treating this as a vanilla-only mod.

Click **WB test: <ID>**, then the field's **Cast once** and **Close test** mouse controls. The helper resolves a unique spell name, verifies its supplied path/level/damage and weapon name, checks name ambiguity and finds the chosen monsters. It uses the generated spell's own weapon; no stand-in overwrites an unrelated effect record. A refused open is reported without closing another mod's field. Normal close and Lua error paths attempt to close only a field the helper successfully opened. Reopen for fresh targets; repeated casts can kill them. No keyboard binding is claimed for these field controls.

This field forces an item-style spell attack. The pinned engine helper extends ranges greater than 1 and below 30 for that attack. It can support manual observation of immediate effects/sounds and target damage in that environment. It cannot establish ordinary casting, path/level eligibility, learning, AI selection, fatigue, true range, initiative, ordinary area targeting, save compatibility or mod interaction. Those need separate fresh-game combat tests. No such observation was performed here.

Afterward close the field, disable the test mod, exit that test game process and remove only the new `<ID>` directory from the disposable profile. Keep the exported source separately. Never use a campaign save to validate reordered new spells.

The previously observed local executable/code fingerprint does not match the pinned extender's known 5.42 profile, and the protected executable remained unchanged during this task. A compatible build and working required hooks are prerequisites. Do not force a mismatched extender build. Actual mod loading, button/field rendering, target behavior and engine state restoration remain untested. Errors should be checked in coe5mod.log. This is the remaining runtime acceptance work, not a claim of a missing syntactic file in the package.
