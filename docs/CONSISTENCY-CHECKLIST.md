# Workbench consistency checks

Concrete findings from the musical_pianist usability audit, 2026-11-06. This is a reusable development checklist, not an in-app tutorial. “Implemented” means code and offline coverage exist; real Windows acceptance remains pending where noted.

| ID / observed issue | Why it confused users | Expected behavior / verification |

| C01 · Vanilla's default source index listed CoE5SE spell definitions alongside weapons. | It looked as if new spell definitions were supported in Vanilla, or filtering them could remove source. | **Implemented:** default weapon view; retained spell count and **Inspect all source**. Open mixed BOM/EOL source, switch target with pending edits, inspect retained spells and export. Assert exact source preservation except explicitly applied edits. |
| C02 · “Target” and “Read as .c5se” occupied the same ordinary toolbar row. | Creation capabilities, parsing rules and file conversion appeared interchangeable. | **Implemented:** detect file format on opening; show source format separately; override inside **Source format…** with preservation warning. Vanilla's empty paste/example defaults to .c5m. Loaded sidecars remain labeled SE-dependent. Pending edits must block interpretation changes. |
| C03 · Vanilla's **Try example** opened the SE spell/weapon pair. | The example contradicted **New weapon** and the target's starting desk. | **Implemented:** native weapon-only example in Vanilla; linked example in SE. Verify both directions, including no automatic target switch or hidden new spell. |
| C04 · Vanilla's creator retained a disabled format selector containing SE choices. | An irrelevant choice implied an available conversion or unsupported native format. | **Implemented:** show static **Native weapon fragment · .c5m**; expose format choice only for SE creation. Verify generated native output has no spell/Lua/dependency text. |
| C05 · Vanilla showed a disabled SE test action and imported mods were called “standalone weapons.” | The explanation assumed source structure that had not been established. | **Implemented:** hide generated-pair test action in Vanilla; label saved values/optional original observation as SE. Only a generated native fragment is called standalone. Verify mixed imports are preserved and not declared Vanilla-compatible. |

## Maintaining this checklist

Use these examples to review related workflows, not as a substitute for understanding the task. Add or update an entry only for an observed, reproducible issue. Record the trigger, user impact, expected behavior, current status and a practical check or evidence link. State whether the evidence comes from a user report, an automated simulation, a rendered desktop check or a game observation. Keep unresolved cases visible and distinguish a fix from verification of that fix.

For any related screen, also check the **target**, **actual file container**, **interpretation override**, **current view scope**, **pending/applied edits** and **runtime dependency** as separate facts. Do not fix a contradictory label by silently converting source or weakening a safety check.
