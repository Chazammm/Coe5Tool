# Vanilla and CoE5SE capability matrix

Scope: Workbench **0.8.0**, native CoE5 format checked against the current manual, and CoE5SE **2.13.0** source. “Both” means a capability exists in both environments, with the conditions shown. It does not certify a whole imported file. Runtime observations are limited to the existing reports (local evidence).

## Capabilities

| Capability | Runtime category | Vanilla CoE5 | CoE5SE | Current Workbench and evidence |
| --- | --- | --- | --- | --- |
| Open and inspect text | Both, offline | `.c5m` interpretation | `.c5m` plus `.c5se` interpretation | Opens/pastes either; this says nothing about dependencies. Current Read as is syntax, not target. UI (local evidence), parser (local evidence). |
| Edit an existing weapon | Both, conditional | Supported native fields in a `selectweapon` or `newweapon` block | Same, with additional forms/traits possible | Ten supported scalar fields; ambiguous/repeated/unknown content preserved. Game IDs and inheritance unresolved. Safeguards (local evidence). |
| Create a weapon | Both | Native `newweapon` with native arguments | Same commands; optional SE extensions | Current creator always makes a linked spell too. A standalone Vanilla creator is proposed, not available. Generator (local evidence). |
| Create a new spell definition | Requires SE | No equivalent general new-spell-definition command established | `newspell`, path, level, weapon assignment and further supported modifiers | Supported narrow linked-pair generator; no arbitrary spell/flag editor. [Official spell commands](https://github.com/musical-pianist/coe5se-docs/blob/main/docs/commands/spells.md). |
| Modify a spell's effect indirectly | Both, conditional | Change an existing weapon used by spells; shared users may change too | Same, plus temporary field substitution | Existing weapon editor covers selected scalar values. WeaponTester spell mode does this kind of editing, not general spell-record editing. |
| Edit spell-definition fields | Requires SE for the supported definition workflow | Native caster/learning commands are separate mechanics | Workbench can edit explicit path, level, damage/weapon assignment in a `newspell` source block | Not an editor for arbitrary built-in spell records. Source parser (local evidence), [spell implementation](https://github.com/musical-pianist/coe5se/blob/9e22d27c32ee15392fc370027d00dbc750b5d19b/src/spell_table.h#L319-L343). |
| Grant existing spellcasting or learning | Both, with different forms | Numeric-path `spellweapon*`; rituals `newspell1/2/3` learn spells | Also named/custom paths where supported | Workbench has no monster/ritual authoring form. These are not substitutes for `newspell`. |
| Export native source | Both | Plain `.c5m` native commands within native limits | Can read native commands too | Export copy preserves source; no Vanilla certification today. A fragment is not a complete installed mod. |
| Export sidecar source | Requires SE | Vanilla does not open `.c5se` | Sidecar supports definitions; same-name main `.c5m` discovers the mod | Current creator offers sidecar fragments and complete experimental test packages. |
| Export mixed `.c5m` | Both, different delivered behavior | Skips `#!@`; guard may intentionally fail load | Activates prefixed lines | Parse success without SE does not deliver ignored features. Current generated test packages require SE explicitly. |
| Reference library | Both, offline | Historical metadata aids inspection | Same data; not a current-runtime enumeration | Known private 5.33 exports: 1,029 spells / 935 weapons. Provenance retained; no current-build or exact Vanilla validation implied. Reference scope (local evidence). |
| Read or change loaded weapon data | Requires SE | No equivalent Lua API | `get("weapon", ...)`; `set` restricted to own new weapons | WeaponTester uses this. Workbench does not currently offer runtime editing. [API](https://github.com/musical-pianist/coe5se/blob/9e22d27c32ee15392fc370027d00dbc750b5d19b/coe5.lua#L600). |
| Experimental field | Requires SE | No verified native equivalent | Main-menu field, draw, Fire/Fight/close | Workbench's generated pair passed specific field tests; uses forced item-style spell cast. [Field contract](https://github.com/musical-pianist/coe5se/blob/9e22d27c32ee15392fc370027d00dbc750b5d19b/coe5.lua#L3913-L3942). |
| Vanilla gameplay validation | Unverified here | Would need an actual SE-free runtime and separate ordinary battle fixture | Running a native mod with SE present is not an SE-free control | Not supplied by the current test button. No new runtime test in this research. |
| Effect/audio preview | Version/context dependent | Native numeric settings exist | Field uses the real game's effect/audio system | No desktop renderer; labels are not previews. Waterball has no captured effect/audio assessment. |

Native entries above are based on Illwinter's [Weapon modding](https://www.illwinter.com/coe5/coe5modding.html), spellcasting-ability and ritual-learning sections. Definition order and name ambiguity matter; selecting a duplicate name may not identify the intended record. Preserve explicit IDs when provenance supports them. This review does not assign current IDs from names.

## Classification rules and guide verification

The developer guide (local evidence) provides the right starting order: file, command, block, arguments. Add dependency and resource-limit checks. Each diagnosis should cite a line and explain the dependency. “Unknown” must be possible: absence from a keyword list is not proof of an extender feature or another mod's command.

| Issue | Verification and conclusion |
| --- | --- |
| `.c5se`, Lua, command scripts and DLLs | Extender loading route; native tokens inside a sidecar still depend on the sidecar loader. `.c5m` may be readable without delivering those features. [Sidecar implementation](https://github.com/musical-pianist/coe5se/blob/9e22d27c32ee15392fc370027d00dbc750b5d19b/src/sidecar.h#L58-L85), guide lines 19–21. |
| `#!@` | Activates extender lines in `.c5m`; Vanilla sees a hash comment. In plain `.c5se`, treat it as a comment, not an instruction to unwrap it. [Prefix handling](https://github.com/musical-pianist/coe5se/blob/9e22d27c32ee15392fc370027d00dbc750b5d19b/src/restart_prompt.h#L9-L17), [sidecar reader](https://github.com/musical-pianist/coe5se/blob/9e22d27c32ee15392fc370027d00dbc750b5d19b/src/sidecar.h#L175-L190); current parser tokenization (local evidence). |
| `requires` | Use plain main `.c5m`, not `#!@requires`. It orders enabled dependencies' DLL/Lua loading; it neither installs nor enables them. Source cuts at `#` before reading it. [Official loading docs](https://github.com/musical-pianist/coe5se-docs/blob/main/docs/commands/mod-loading.md), [reader](https://github.com/musical-pianist/coe5se/blob/9e22d27c32ee15392fc370027d00dbc750b5d19b/src/mod_order.h#L195-L210). |
| Intentional dependency guard | `needs_script_extender`, `needs_coe5se`, and WeaponTester's old long form are registered no-ops in SE. The first is documented to fail deliberately in Vanilla. [Guard source](https://github.com/musical-pianist/coe5se/blob/9e22d27c32ee15392fc370027d00dbc750b5d19b/src/mod_command_hook.h#L141-L149). Put a guard on a plain `.c5m` line for required SE content. |
| Context changes meaning | `level` or `burnforest` inside a new SE spell are not the native ritual behavior. `name` following `selectspellpath` changes a path. [Spell hook](https://github.com/musical-pianist/coe5se/blob/9e22d27c32ee15392fc370027d00dbc750b5d19b/src/spell_table.h#L468-L494), [path hook](https://github.com/musical-pianist/coe5se/blob/9e22d27c32ee15392fc370027d00dbc750b5d19b/src/spell_paths.h#L194-L204). Do not classify these tokens globally. |
| Numeric versus quoted paths | Numeric `spellweaponbonus 4 1` is a native monster ability form. Quoted path names in those abilities and `newspell1/2/3` use an SE rewrite. [Path argument hook](https://github.com/musical-pianist/coe5se/blob/9e22d27c32ee15392fc370027d00dbc750b5d19b/src/spell_paths.h#L170-L226). The guide's exact silent-drop outcome in Vanilla was not reproduced here. |
| Names instead of offsets | Quoted monster/ritual names in offset-based commands are translated by SE into relative numeric offsets. [Implementation](https://github.com/musical-pianist/coe5se/blob/9e22d27c32ee15392fc370027d00dbc750b5d19b/src/offset_names.h#L92-L134). Guide line 47's exact native fallback of -1 remains developer-reported, not observed here. |
| False flag values | SE intercepts `flag 0` for supported record flags; this includes weapon flags. Do not output that as verified native flag removal. The guide itself leaves native behavior unchecked. [Flag hook](https://github.com/musical-pianist/coe5se/blob/9e22d27c32ee15392fc370027d00dbc750b5d19b/src/monster_flags.h#L89-L107). |
| Weapon extensions | `onlyaffects`, `doesntaffect`, `doubledmgvs`, `noexplode` need SE. Native chains and `clearwspec` must not be mislabeled as SE merely because WeaponTester uses them. [Trait commands](https://github.com/musical-pianist/coe5se/blob/9e22d27c32ee15392fc370027d00dbc750b5d19b/src/weapon_traits.h#L470-L475), [noexplode](https://github.com/musical-pianist/coe5se/blob/9e22d27c32ee15392fc370027d00dbc750b5d19b/src/no_explode.h#L365). |
| Incomplete keyword inventory | Guide line 30 calls `+minunitshere` native since 5.41; source lists it among event triggers. The current manual search did not independently locate it and no version-history check was made. Keep this case version-dependent; never classify it as another mod solely from a missing keyword. [Trigger list](https://github.com/musical-pianist/coe5se/blob/9e22d27c32ee15392fc370027d00dbc750b5d19b/src/faction_names.h#L13-L18). |
| Remaining guide examples | Named classes, recruitment arguments, `aiclass 2`, named planes and corpse kinds are outside the first weapon classifier. Their precise Vanilla outcomes remain guide claims or explicitly unchecked. Preserve them as unsupported/needs review, rather than certifying a whole file. Guide lines 49–54. |
| Baseline engine behavior | Guide line 94 identifies always-on fanpatches. This review did not audit their complete runtime effect. An SE-enabled run cannot establish an SE-free Vanilla baseline. |

The guide's scope line says **2.13.0 / 5.42**. The actual pinned release has version **2.13.0** and a known-build entry for **5.43**, with Windows code hash `11ea0b5dc7f80c7ec32efef77e3d0b2e13c10a065786be3cf48982ef94e4bba6`. Treat this as a correction to the guide's header, not evidence for a forced 5.42 launch. ## Limits and scope

Official [limits documentation](https://github.com/musical-pianist/coe5se-docs/blob/main/docs/commands/limits.md) describes additions by **all enabled mods together**: 3,799 native / 5,799 SE weapons, no native additional spells / 3,000 SE additional spells, and no native additional magic paths / 400 SE paths. These are not total record counts, available slots in a user's session, or Workbench UI limits. Weapon source reserves the mod range from 1200 and adds 2,000 slots; spell relocation reserves 3,000 additions. [Weapon capacity](https://github.com/musical-pianist/coe5se/blob/9e22d27c32ee15392fc370027d00dbc750b5d19b/src/table_move.h#L27-L30), [spell capacity](https://github.com/musical-pianist/coe5se/blob/9e22d27c32ee15392fc370027d00dbc750b5d19b/src/spell_table_move.h#L9-L10).

A file using only native vocabulary can still exceed native capacity or depend on another mod. Static inspection of one file cannot count the entire enabled mod set. The Workbench creator's path 1–69, levels 1–3, two damage types and simple area/flight subsets are deliberately narrower than the engine. Do not label them engine-wide restrictions. Actual generator bounds (local evidence).
