## Supported workflow and API boundary

Fixed melee, fixed ranged and ranged visual comparisons accept **1–200 copies of one searchable native defender type**. One Spearman #13 is the default. Changing the count invalidates the preparation. The next package retains the original source, private carrier, attack payload and selected visuals. The target group belongs to the isolated CoE5SE test. Native export contains only the weapon.

The generated-pair helper already passes a single enemy ID and its count to `openTestField`. The pinned 2.13.0 implementation accepts 1–200, creates each enemy under player 24 at (1,1) and can return success with a partial allocation. The standalone helper enumerates living units on that square before combat. Missing or additional defenders, duplicate instance IDs and an unexpected monster type abort the battle and enter field cleanup. A resistance getter failure leaves only that member’s reading unavailable. Fixed group receipts record every member as `unitN=instance,resistance`. Comparisons bind an independent roster to each saved battle. Group size 1 remains compatible with earlier receipts. **Mixed types and sequential waves remain unsupported.** The field API accepts a single monster ID and provides no field-owned operation to add another type. The generic map spawn performs terrain fitting, army rebuilding, conquest checks, sight updates and a map-cache reset. The field’s close routine restores its square, team slots and several game globals. It provides no corresponding rollback contract for those extra map operations. A field-owned roster API that accounts for allocation and cleanup would be the appropriate dependency for mixed groups.
